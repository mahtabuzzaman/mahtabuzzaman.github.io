Field guide

What each thing in the game means, and what it means in a real data pipeline.

#1042 ✓Clean row

In the game: let it land. Each clean row that reaches Gold scores points, and shooting one by mistake costs points.

In real pipelines: a row that passed every check: the right columns, the right types and no missing keys. Reports and dashboards read rows like this from the Gold layer.

NULLMissing value

In the game: shoot it before it lands.

In real pipelines: a required field is empty, such as an order with no customer ID. Joins quietly drop the row, or totals come out wrong.

How teams fix it: check required columns as data moves into Silver, and send failing rows to a quarantine table where someone can fix them, instead of deleting them.

copy #1042Duplicate row

In the game: the copy falls first. Shoot it, then let the original land.

In real pipelines: the same record loaded twice, often because a pipeline run was retried or two extracts overlapped. Counts and revenue double without anyone noticing.

How teams fix it: keep one row per key, for example with ROW_NUMBER() OVER (PARTITION BY id ORDER BY updated_at DESC) = 1, or load with a MERGE on the key.

#@!%Corrupt row

In the game: it wobbles from side to side. Shoot it.

In real pipelines: values that don’t fit the schema: text in a number column, impossible dates or broken characters. It often shows up when a source system changes its format without warning, which is called schema drift.

How teams fix it: enforce the expected schema when reading data, validate types, and alert the team when a source changes shape.

SKEWData skew

In the game: big and slow. It takes six hits, and if it lands it breaks two Gold bars.

In real pipelines: Spark splits data into partitions and works on them in parallel. When one key has far more rows than the rest, such as one giant customer, a single task does most of the work while the others wait, and the whole job slows down.

How teams fix it: let Adaptive Query Execution split skewed partitions, broadcast the smaller table in a join, or “salt” the busy key so its rows spread across more partitions.

ShieldGold tokens

In the game: shoot a token to use it. Dedupe removes every copy on screen, Shield blocks the next bad row, Slow-mo halves the speed for 6 seconds, and Spread fires three shots at once for 8 seconds.

In real pipelines: Shield works like a data quality gate that stops a bad row before it reaches a report, and Dedupe is the cleanup step that removes copies.

Bronze, Silver and Gold

In the game: the three bands of the screen. Rows fall from Bronze through Silver, and your job is to keep Gold clean.

In real pipelines: this is the medallion architecture. Bronze keeps data exactly as it arrived so any load can be replayed, Silver cleans and standardizes it, and Gold models it for reporting so every metric is defined once.
